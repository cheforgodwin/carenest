# Provider self-service jobs and Firebase Cloud Messaging

Approved providers browse verified paid, unassigned, unheld jobs through POST /api/jobs. The board contains limited job/earnings summaries; customer phone, full address and other private customer fields are available only after acceptance. POST action accept claims a job transactionally using the authenticated provider profile. Competing claims cannot overwrite the first provider. Existing provider-owned marketplace orders continue through their normal acceptance flow. Rider assignment remains managed by administrators.

The user-supplied Firebase Web Push public key is configured in messagingService.js and can be overridden with VITE_FIREBASE_VAPID_KEY. Enable notifications requests browser permission from an explicit click, registers /firebase-messaging-sw.js under a separate push scope, gets an FCM token, and sends it to the authenticated notification API. The original /sw.js remains responsible for offline caching.

Each device is stored in pushSubscriptions/{SHA256(token)} and users/{uid}/fcmTokens/{SHA256(token)}. Tokens are server-managed, not exposed to browser Firestore reads, and support multiple devices. Registering a shared device moves ownership from the previous account. Enable/disable preferences survive navigation. Token refresh happens on later opted-in sessions. Logout attempts to unregister/delete the current token; signing out still works if the network is unavailable. Stale invalid tokens are removed on send.

Verified payment outcomes, provider acceptance, saved order status changes, rider assignment/delivery, completion, and recorded transfers trigger notifications. The sender reads the actual saved order, reserves a deduplicated event and sends generic messages without private phone/address/amount data. Paid open jobs alert approved providers. Message clicks only open same-origin dashboard paths. Foreground messages appear in an accessible banner. FCM acceptance does not prove device delivery or that the user read the notification; push is best effort and must not roll back payment/workflow operations.

Browser requirements: HTTPS and notification support. On iOS, use a Home Screen web app. Permission denial is handled with browser-settings guidance. An actual signed-in user must enable notifications on their device before live delivery can be tested. No test creates a charge or claims a real job.

The gated configure-messaging build helper verifies/enables only FCM and FCM Registration APIs on carenest-11319 and checks the actual paid-job query. It requires CARENEST_CONFIGURE_MESSAGING=1 and uses protected build credentials. No private Firebase credentials are emitted into the worker.
